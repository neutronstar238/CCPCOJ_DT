# CCPCOJ_DT · CSGOJ 部署工作台

面向竞赛运维的 Windows 本地部署工具：用浏览器管理 SSH 连接、Web 与 PCJ 评测机，在本机准备镜像，再通过内网分发、初始化或更新服务器。也支持在本机 WSL 中运行 Web 和评测机。

**当前工作台版本：v1.10.3，首次公开发布。** 工作台版本、Linux 部署程序 Release 和 OJ 镜像标签是三个独立的版本号，请按实际需求分别选择。

- [下载 Windows 完整包](https://github.com/neutronstar238/CCPCOJ_DT/releases/latest)
- [首次发布说明](docs/RELEASE-v1.10.3.md)
- 上游 OJ / Linux 部署程序：[SZTU-ACM/CCPCOJ-2](https://github.com/SZTU-ACM/CCPCOJ-2)

本仓库是部署工作台的源码仓库。发布包包含 Windows 执行程序、网页、节点模板、源码、操作文档与文字验证记录；不附带 OJ 镜像、Linux 部署程序、个人配置、私钥、密码导出文件或验收截图。

## 功能总览

侧栏按下面的顺序组织：

| 页面 | 主要功能 |
| --- | --- |
| SSH 密钥管理 | 独立维护连接，生成或复用 Ed25519 密钥，配置公钥，测试免密登录，扫描已有 web / pcj 前缀密钥，同步本机 SSH 别名 |
| 节点配置 | 添加 Web / 评测机，配置 IP、账号、提权、目录、启用或备用、绑定 Web、pods；XLSX 预览与导入；主机图形界面、休眠和性能设置 |
| 版本与镜像分发 | 查询上游 Release / 镜像标签，下载或导入部署程序和镜像，识别本机已有镜像，管理缓存、选用归档、内网分发 |
| 批量更新 | 同步运行版本和服务器已有镜像，逐台指定目标版本，全选 PCJ / Web，自动区分已有部署更新与首次初始化 |
| 状态与主备切换 | 检测 SSH 与业务服务、实际运行 pods；启动服务、调整 pods、更新 Web 地址、备份、受控主备迁移、数据库迁移 |
| 部署资料 | 查看部署资料，按节点或全部导出管理员、评测账号和数据库业务口令 |
| 本地部署 | 选择 WSL 发行版和 Linux 路径，部署或更新本地 Web / PCJ，查询版本、状态，开启或关闭所选服务 |
| 使用说明 | 在工具内查看操作帮助 |

普通配置在输入完成、失焦或选择变更后自动保存，界面显示结果。部署、更新、迁移、导入确认、删除缓存等需要主动执行或确认；保存配置本身不会自动改变运行中的服务器。

## 环境要求

### Windows 管理电脑

- Windows x64；正式发布包自带 Python 运行时和 SSH 依赖，无需另装 Python、Node.js、Ansible 或 PuTTY。
- 能通过 SSH 访问目标主机；在线获取版本与镜像时，管理电脑需要访问 GitHub 和所选 Registry。
- 保留足够磁盘空间存放镜像层、归档及备份；具体需求取决于镜像和业务数据大小。
- **下载、导入归档和内网分发不要求安装 Docker Desktop。** 读取或导出已有 Docker 镜像时，才需要可用的本机 Docker Linux 引擎。

### 远程服务器

- 本工具主要面向 Ubuntu 24.04 LTS、Linux amd64；准备已存在的 SSH 登录账号和可用的 sudo / root 提权方式。
- 没有 Docker 时可在初始化阶段安装；apt 系统软件包下载仍需要网络。镜像内网分发不等于从空系统开始完全离线安装。
- 已有部署必须使用正确的项目目录和凭据；不要把不完整部署、残留数据目录当成空白节点。
- 数据库迁移需要事先挂载好的本地磁盘及 rsync，不会格式化磁盘。

### 本地部署

需要 WSL 2 Ubuntu 24.04 x86_64、systemd 和该发行版自己的 Docker。不要启用 Docker Desktop 对目标发行版的集成；工作台会检查 Docker 所在环境，防止把 WSL 数据路径交给另一套文件系统。

## 下载、校验与启动

1. 在 Release 下载 `CSGOJ-Deployment-Console-Windows-v1.10.3.zip` 和同名 `.zip.sha256`。GitHub 自动生成的 Source code ZIP 只有源码，没有打包好的程序。
2. 在下载目录运行下面的 PowerShell 命令，将输出与 `.sha256` 文件第一列比较：

   ```powershell
   Get-FileHash -Algorithm SHA256 .\CSGOJ-Deployment-Console-Windows-v1.10.3.zip
   Get-Content .\CSGOJ-Deployment-Console-Windows-v1.10.3.zip.sha256
   ```

3. 解压完整目录，双击 `启动部署工作台.cmd`，保持执行程序运行。
4. 程序打开默认浏览器，只监听 `127.0.0.1`。这是本机管理界面，不是公开的局域网管理站。

关闭网页不一定终止后台程序。替换或删除程序目录前先退出执行程序；如果 Windows 提示目录被占用，检查对应程序及以该目录为工作目录的终端。退出工作台不会自动停止已部署的远端或 WSL 业务服务。

## 第一次远程部署

1. **SSH 密钥管理**：添加连接，填写 IP、SSH 用户、端口和私钥名称。生成 / 复用密钥，配置服务器公钥并验证纯密钥登录。SSH 账号必须已在服务器上存在。
2. **节点配置**：添加 Web 和评测机，填写项目目录、提权方式与必要凭据；评测机绑定对应 Web，设置 pods。备用节点只准备资源。
3. **版本与镜像分发**：选择已发布的 Linux amd64 部署程序，或上传本地文件；选择实际存在的 OJ 镜像标签，准备对应归档。版本默认留空，不自动选择最新版。
4. **首次 Web 初始化**还需要 MySQL、Nginx、phpMyAdmin 三项依赖镜像；仅更新程序时默认不下载这三项。依赖标签以界面和所选部署程序兼容要求为准。
5. 可先把镜像分发到勾选节点；分发只上传、校验、`docker load`，不启动或替换应用容器。
6. 到 **批量更新** 同步服务器版本与镜像，选择节点和目标版本，核对维护确认后执行。Web 先于评测机处理。
7. 在状态页检测：Web 验证登录及样式资源；评测机检查容器及新心跳，并显示检测当时的实际运行 pods。

已有完整部署保留配置更新；未托管的完整部署需要验证原凭据后接管；空白节点才初始化。残留数据、缺失容器、异常挂载、未完成事务或检测失败不会被直接判为空白。更新失败会记录结果并停止批次，已成功的节点不自动撤销。

已有 Web 更新保留数据库等基础容器、业务数据、口令和运行参数，只替换 OJ 应用容器；评测机更新保留账号、pods 和绑定关系。此保护机制不能代替业务备份，请在维护时段执行。

## 版本下载、缓存与分发

### 在线准备

- 查询官方仓库的公开 Release，包含已发布的 `exp` 标签；选择该 Release 的 Linux amd64 附件。不存在的版本不会悄悄换成别的版本。
- 镜像版本列表来自上游接口。输入框也支持手动填写；标签存在与否以实际请求结果为准。
- 优先下载源支持腾讯云、Docker Hub、自定义 HTTPS 源。腾讯云优先时失败再尝试 Hub；Hub 优先时顺序相反；自定义源失败后尝试腾讯云和 Hub。
- 工具直接通过 Registry V2 下载 Linux amd64 内容，最多四层并行；校验清单、压缩层摘要和解压层 diff_id，再生成标准 Docker-save 归档。
- 已校验层、已有归档和可用的本机 Docker 缓存可复用。仍会读取远端清单，避免同名 exp 标签更新后误用旧内容。
- 代理候选需要通过 HTTP CONNECT 检查，排除 53000 控制端口。不修改系统代理或 Docker 永久配置。

选中优先源不代表禁止回退；日志会显示各源尝试结果。同名标签在不同仓库可能有不同内容，工具记录实际镜像身份并在分发后核验。网络、镜像源可用性和上游速率限制仍会影响下载。

### 已有本地文件或 Docker 镜像

- 上传 Docker-save 格式的 tar 归档，按内容读取真实标签、平台和镜像身份；不是仅根据文件名猜测。
- “识别已有本地镜像”检查工具缓存、常用本地目录及已运行的本机 Docker，列出可用候选。不会连接远程 Docker，也不会自动启动 Docker。
- 选择归档后应用其真实版本和文件路径；选择 Docker 镜像时可先导出到工具缓存，再分发。
- 切换缓存版本会清除不匹配的旧路径，防止版本与文件不一致。
- 同一个版本有多个候选时，请核对并明确选择。未匹配到唯一目标时不会擅自选用。
- 删除缓存需要二次确认，只删除工具管理的归档和相关选用记录，不删除原始导入文件或服务器数据。

默认下载、导入和“刷新本地缓存”共用 `%LOCALAPPDATA%\CSGOJDeploy\images` 及其索引。使用 `--data-dir` 时以该资料目录为准。下载中的层缓存不等于已经生成、可分发的完整归档。

### 内网分发与更新

分发优先使用所选本地归档。批量更新优先使用服务器已经拥有的目标镜像，缺少时才从本机上传。分发过程检查归档 SHA256、实际配置摘要、文件系统层和平台；容器运行时报告的父索引摘要不直接等同于镜像配置 ID。服务端部署使用 `--no-pull`，不会为缺少的 OJ 镜像自行访问外网。

## SSH 连接与配置同步

- 私钥保存在 Windows；只向服务器用户的 `authorized_keys` 追加公钥，不覆盖其他公钥。
- SSH 认证成功不等于拥有 sudo 权限，提权密码单独配置。
- 修改 IP、用户名或端口时可保留同一个私钥名；本地保存会同步使用该私钥名的已保存节点及本工具管理的 SSH 别名。
- 随后可使用 `ssh 别名`。如果换了服务器或登录用户，仍需确认新目标授权了相应公钥。
- 主机公钥发生变化时停止连接，不自动删除旧指纹；SSH 别名与其他密钥冲突时保留原配置并提示。
- 可扫描现有 `web` / `pcj` 前缀密钥，预览并选择后导入；同名不同内容的私钥不会覆盖。

## 节点模板与普通配置

`templates/CSGOJ节点导入模板.xlsx` 可批量填写节点和全局设置。先预览、再确认导入；按节点名称合并，未列出的已有节点保留。导入不会自动连接或部署。

- 示例 IP 留空；请填写自己的地址。
- `备用(0/1)`：0 为启用，1 为备用。
- 密码可留空并在界面补填；填写到 Excel 中的密码是明文。
- 项目目录默认 `/home/ccpc00/cpc`，可在准备前修改；同机不同实例应使用各自专用目录。
- 版本未选择时保持留空。普通配置自动保存，错误会提示，不会用保存失败的值假装部署成功。
- 已托管节点的身份、目录和业务口令有额外保护，不能通过普通表格导入随意覆盖。

## 状态、pods、备份与迁移

### 状态与 pods

SSH 不可用表示连接或认证失败，不等于主机一定关机。服务状态单独显示容器和业务检查结果。PCJ 的 pods 行来自最近一次检测，不用计划数量冒充实际运行数。

已有容器停止时可一键开启；容器缺失需检查部署。调整 pods 时先在节点设置目标数，再在维护时段应用；工具检查资源、队列并尝试在失败后恢复原数量。心跳正常和容器数匹配不是每个 pod 都通过真实提交的证明。

### Web 备份与主备切换

支持受控停机冷备份和迁移：暂停相关服务，保存完整数据到 Windows，校验 SHA256，恢复或切换，并检查登录、样式及关键数据数量。原始数据和快照保留；失败尝试恢复，恢复失败会明确记录。

此功能不是实时复制、双主或失联后的自动故障切换。切换后旧站保持停止，不会自动成为同步副本。详见 [迁移与恢复](docs/03-迁移与恢复.md)。

### 数据库 SSD 目录

- 首次初始化可指定已挂载磁盘下的空数据库目录；留空使用项目默认数据路径。
- 已部署节点先“检测实际存储位置”，查看项目、数据库、代码、题库和 Docker 的设备、挂载与空间。
- 迁移需要空目标目录、维护确认和二次确认。停止相关服务及 MySQL 后，使用 rsync 保留属性并校验，再通过 bind 挂载保持官方数据路径。
- 记录磁盘 UUID 并检查挂载，避免 SSD 未挂载时误写系统盘。Docker 挂载依赖可能影响同机其他容器的开机启动。
- 原数据保留；未完成事务使用恢复入口。不会自动格式化磁盘、迁移 Docker 全部镜像或随意删除残留副本。

## 本地 WSL 部署

1. 选择已安装的 WSL 发行版，填写 Linux 根目录（默认 `/srv/csgoj-local`）。Web 和评测机使用独立子目录。
2. 复用相同 Windows 部署程序和镜像缓存，配置本地 Web 端口、管理员、PCJ pods 与目标版本。
3. PCJ 可连接本地 Web，或使用外部 Web 地址及其已有评测账号。外部模式不会自动修改外部站点或注册账号。
4. 勾选 Web、PCJ 或两者，确认后部署 / 更新。已有实例保留数据和配置。
5. “获取本地版本与状态”读取实际版本与容器状态；“一键开启所选服务”恢复已有服务。
6. “关闭所选服务”仅停止所选容器，保留容器、数据、配置和镜像，不关闭其他服务或整个 WSL。

Windows 上 WSL 虚拟磁盘的位置由 WSL 管理；页面中的路径指发行版内部 Linux 路径，不是搬迁现有 VHDX。详细要求见 [本地部署说明](docs/10-本地部署-WSL.md)。

## 本地资料与口令

默认资料目录为 `%LOCALAPPDATA%\CSGOJDeploy`，与解压后的程序目录分离：

```text
config.dpapi            节点配置与业务口令
ssh-connections.dpapi   独立 SSH 连接资料
local-deploy.dpapi      本地 WSL 部署配置
known_hosts            已登记主机公钥
keys/                  SSH 私钥与公钥
tools/                 Linux 部署程序缓存
images/                镜像归档、已校验层和索引
logs/                  执行日志
backups/               冷备份和校验清单
```

口令配置通过当前 Windows 用户的 DPAPI 加密；不要直接编辑加密文件，也不要把它视作可跨用户恢复的备份。私钥、快照和导出的业务资料需要单独妥善保存。

“部署资料”可按勾选节点或全部导出 TXT / 部署资料：管理员、评测账号、MySQL root、数据库业务及 phpMyAdmin 口令来自本机保存记录。不会为了导出而更改服务器密码；在站点自行改密后，本机旧记录可能不再有效。导出文件含明文口令，不应提交到公开仓库。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| `ssh 别名` 仍要求密码 | 本机 SSH config 是否同步、User / HostName 是否正确、新用户是否配置了相应公钥 |
| sudo 失败 | 登录密码与提权密码是否一致、账号是否有 sudo 权限；公钥登录不会提供 sudo 密码 |
| 在线版本查询超时 | 本机网络、代理、GitHub / Hub 可达性；已有缓存的分发不要求先查询在线列表 |
| 优先源失败后出现 Hub 日志 | 属于按镜像回退流程，查看日志中的实际成功源和标签 |
| 已分发但服务版本未变化 | 分发不部署，仍需到批量更新选择目标版本执行 |
| 磁盘、数据或挂载异常 | 先检查存储位置和未完成事务，不能把现有数据当空白初始化 |
| 目录无法删除或替换 | 退出对应执行程序及占用目录的终端，保留独立资料目录 |
| 本地 WSL 数据路径错误 | 检查所选发行版与 Docker Desktop 集成，使用该发行版自己的 Docker |

## 源码开发与打包

仓库根目录就是源码。Windows Python 3.12：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe server.py
```

独立测试资料目录可用：

```powershell
.\.venv\Scripts\python.exe server.py --no-browser --data-dir .\state
```

运行自动回归（JavaScript 测试需要 Node.js 和 npm）：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
npm install
npm test
```

构建 Windows 完整包：

```powershell
.\.venv\Scripts\python.exe build.py
```

产物写入 `dist/releases/`：ZIP、`.zip.sha256` 和 `.zip.privacy.json`。包内另有 `SHA256SUMS.txt` 逐文件清单和第三方依赖说明。脚本只收录允许的源码和文档；验收目录只收 Markdown。脱敏检查失败会报错，此时不要发布已生成的候选 ZIP。

构建阶段目录已存在时会停止，避免无意覆盖旧产物；先保留并重命名该版本的 `dist/release-v...` 目录，再重新构建。测试目录内的 `*_check.py` 是额外环境检查脚本，部分会创建实际服务或修改测试环境；普通回归使用上述 `test_*.py` / `*.cjs` 命令，不要对生产配置盲目执行全部脚本。
