# CSGOJ 部署工作台（Windows v1.14.7）

面向部署人员的本地 HTML 操作界面与 SSH 执行程序。目标服务器已经安装 **Ubuntu 24.04 LTS x86_64**，不需要重新安装 Ubuntu。

## 启动

v1.14.7 默认部署 CSGArena v1.16.2。DT 部署服务端后，可按已保存的 HTTPS 地址打开管理控制台，由场控分发客户端并核对机位上线。旧的 DT 逐机部署入口收在兼容流程中。详见 [场控部署](docs/arena-deployment.md)。

v1.14.6 新增“本次目标 IP”筛选，可对已保存清单中的部分机位预览、推送、部署或查询，不改写其他机位的配置。

v1.14.5 为 Ansible 任务加入超时：普通远程步骤 60 秒、安装包传输及安装登记 300 秒，防止单台 SSH 执行通道不响应卡住整批部署。

v1.14.4 修复打包版缺少 TLS 证书策略文件，导致 Release 扫描及 HTTPS 下载失败的问题。打包时加入真实 EXE 的 TLS 上下文自检，保持证书和主机名校验开启。

v1.14.2 修复管控部署首次 SSH 连接报 `stdin is not interactive`：页面显示首次主机指纹，确认后继续原任务；Windows 已信任的公钥传入 WSL 任务独立目录，指纹变化仍拒绝连接。

v1.14.1 修复 SSH 表格私钥／解锁口令输入框挤占操作结果的问题：输入框上下排列，固定列布局，窄窗口可在表格内横向滚动。灰色提示为通用文字，本机默认路径仍只读取本机加密设置。

v1.14.0 新增外部私钥与可选解锁口令登录，覆盖 SSH 管理、OJ 节点、管控服务端和选手端。新增连接默认 root；本机默认私钥单独加密保存，发布包不附带本机配置。选手端可先保存待绑定清单，再统一绑定服务端。见 [私钥登录说明](docs/private-key-login.md)。

v1.13.0 新增扫描和推送有线优先：每次任务动态读取 Windows 网卡、IPv4 与路由，同等目标路由优先物理以太网；WSL Ansible 的 SSH / WinRM 连接通过 Windows 出口转发。扫描界面和任务日志显示所选接口与回退，详见 [网络出口说明](docs/network-egress.md)。

v1.12.1 新增管控 Release 全量分页扫描与版本选择，显示正式版／预发布／草稿及安装包完整性；选择并应用指定版本后，可先拉取本页 Linux／Windows 安装包，再仅推送到目标暂存目录，或沿用部署、启动及登记流程。保留 v1.12.0 的网段扫描和批量凭据设置。当时的默认管控产物为 `SZTU-ACM/CSGArena v1.11.0`。使用步骤见 [赛场管控部署说明](docs/arena-deployment.md)；实机安装、登记和策略验收仍需隔离赛场机器。

1. 解压整个工具包，不要只拖出 exe。
2. 双击 `启动部署工作台.cmd`。它启动本机服务并打开默认浏览器。
3. 保持程序窗口打开。界面只监听 `127.0.0.1`，不是给局域网其他人访问的管理站。

包内已包含 Windows Python 运行环境和 SSH 依赖，OJ 部署不需要另装 Python、Node.js、Ansible 或 PuTTY。新增赛场管控部署使用本地 WSL 中的 Ansible，可通过页面准备控制端依赖。OJ 目标机使用官方 `csgoj-deploy`；Web/PHP/数据库/评测代码来自镜像，不额外克隆一份仓库源码。

## 从空白服务器开始

页面按独立功能分为 **SSH 密钥管理、节点配置、版本与镜像分发、批量更新、状态与主备切换、部署资料、本地部署、使用说明**。检测在线、备份和切换可以直接使用，不需要重跑部署。

## 批量更新与首次初始化

1. 点击“同步服务器版本与镜像”，读取当前容器版本和服务器已有镜像标签，包括已通过内网分发的版本。勾选节点时只同步所选节点；未勾选时同步全部。同步不停止或替换服务。
2. 勾选本次需要操作的节点，为每台选择或填写目标版本。目标版本默认留空，填写后自动保存到本机。
3. 核对检测结果和维护确认框，点击“部署 / 更新所选节点”。已有完整部署自动保留配置更新；未托管的完整部署先验证原凭据并接管；空白节点首次初始化。Web 先于评测机执行。
4. 优先使用服务器已有目标镜像，缺少时才从 Windows 本地缓存分发。已有 Web 更新只替换应用容器，保留数据库等基础容器、数据、原业务口令和运行参数；评测机保留原 pods 和账号配置。首次初始化需要官方部署程序和依赖镜像；备用只准备资源。

若发现残留数据但容器缺失、Docker 未运行或未完成的更新事务，会明确停止并要求检查，不能当作空白机器重新初始化。同步失败也不会判为可初始化。执行前会再次检查服务器实际状态。更新失败沿用原有备份与回滚机制，批次停止，已完成的节点保留。

## XLSX 一键导入

包内 `templates/CSGOJ节点导入模板.xlsx` 也可在页面直接下载。

1. 在“节点”表填写服务器 IP，删除不需要的示例行。`备用(0/1)` 填 **0=启用、1=备用**。Web 和评测机都适用。
2. 密码可以留空，导入后在页面编辑补填；在 Excel 填写的密码是明文。
3. “全局设置”表填写版本、镜像源和三个系统选项；关闭图形界面、永不休眠、性能模式均用 0/1。
4. 选择 XLSX 后先展示导入预览。按名称合并同名节点，未列出的已有节点保留。
5. 点击“确认导入配置”后，页面显示导入结果并保存；**不会连接服务器或自动部署**。
6. 先到“版本与镜像分发”准备所需镜像，再到“批量更新”同步服务器版本，选择节点及目标版本，核对后执行。

示例的 IP 列故意留空，避免把模板里的演示机器误当成真实目标。私钥名和站点名可以在准备前修改。已托管节点不会允许导入覆盖它的身份、目录和业务口令。

| 填写项 | 说明 |
| --- | --- |
| 镜像标签 | 例如 `2.0.281-exp`。这是可编辑的初始值，不代表自动追踪最新版 |
| 部署工具 Release | 例如 `2.0.271`；从 Release 列表选择实际标签与 Linux amd64 附件，支持已发布的 `-exp` |
| 官方部署程序 | 选择本地 Linux x86_64 文件，或从官方 GitHub Release 下载 |
| 镜像源 | 在资源模块选择腾讯云、Docker Hub 或自定义 HTTPS 镜像源，仅影响本次本机下载 |
| 节点名称 | Web 与 pcj 均可任意增加；评测机默认从 `pcj01` 顺序编号，可在准备前修改 |
| SSH 用户与密码 | 例如 `ccpc00`。第一次用于安装本工具生成的公钥；后续使用私钥 |
| 提权方式 | sudo 填登录账号的 sudo 密码；su 填 root 密码；直接 root 要求 SSH 用户就是 root |
| 私钥名称 | 只填文件名，例如 `web-exp`、`pcj01`；不会覆盖你原来的 `.ssh` 私钥 |
| 项目目录 | 默认 `/home/ccpc00/cpc`，不存在时建立。同机不同节点使用不同专用目录 |
| 管理员账号/口令 | 可填初始管理员；口令留空时自动生成。已初始化站点不会被重置密码 |
| 启用 / 备用 | 启用节点运行服务；备用节点只准备 Docker、部署程序与镜像，并断网运行一次检查容器 |
| 绑定 Web | 每台评测机选择它服务的 Web，不能把启用评测机绑定未启用备用 Web |
| pods | 默认 1。官方工具每 pod 4 核/4 GB，另预留 2 核；6 核机器使用 1 pod |

数据库 root、数据库业务账号、phpMyAdmin 三个口令独立使用密码学随机数生成。保存后不会每次重新生成。它们是供服务使用的随机口令，不是对固定文本做一个可预测的“hash”。

### 实际执行步骤

1. SSH 连接并登记主机公钥指纹；以后主机密钥变化会拒绝连接。
2. 在 Windows 资料目录生成 Ed25519 私钥，仅把公钥追加到远端 `authorized_keys`，不覆盖其他人的公钥。
3. 断开后用新私钥重新登录，验证密钥可用。
4. 检查 Ubuntu 24.04 x64、部署目录和现有容器，避免误覆盖既有站点。
5. 使用 SFTP 上传官方部署程序及执行模块，验证 SHA256。功能相当于之前手动 SCP 上传。
6. 若 Docker 未安装，执行 apt 安装 `docker.io`，启用 Docker 和 SSH。**密钥不是 sudo 权限**，提权密码会单独使用。
7. 按勾选项关闭图形登录、设置永不休眠和硬件支持的性能模式；原设置保存在服务器 `private/host-settings.json`。
8. 先在 Windows 下载或导入镜像归档，再通过 SSH 分发、验证 SHA256 和镜像 ID、docker load。服务器不拉镜像，官方部署指定 --no-pull。
9. 运行 `--network none` 的临时容器检查 PHP，或 C++ / Python 运行环境；备用节点到此停止。
10. 启用 Web 调用官方 `up`，检查容器、初始化管理员、验证登录与 CSS 资源；启用评测机创建专用账号，调用官方 `judge` 并观察新的 OJ 心跳。

没有部署到现有机器上试运行本工具。交付前完成了自动化、真实本地 SSH/SFTP、浏览器和 Linux 文件恢复检查；**新的整机部署与 Web 冷迁移仍应先在可弃置环境演练**。详见 [验证记录](docs/05-验证记录.md)。

## 本地资料在哪里

默认目录：`%LOCALAPPDATA%\CSGOJDeploy`。页面左下角显示实际路径。

```text
config.dpapi         当前 Windows 用户加密的配置与口令
known_hosts          已登记 SSH 主机公钥
keys/                私钥与 .pub 公钥（采用填写的名称）
tools/               选择或下载的 Linux 部署程序
images/              Docker-save 归档和标签/选用记录
logs/                隐藏口令后的执行日志
backups/             Web 冷快照与 SHA256 清单
```

“下载部署信息与口令”会下载 JSON，含业务口令与节点资料，不含 SSH 登录/提权密码。这个下载文件是明文，适合部署人员单独保存；不要上传到公开仓库。私钥不会发往服务器。

示例手动连接（PowerShell）：

```powershell
ssh -i "$env:LOCALAPPDATA\CSGOJDeploy\keys\pcj01" ccpc00@<评测机IP>
```

IP 变动时保留节点名称和私钥名，修改 IP 保存，再执行节点检查。Web IP 改变后，针对关联评测机使用“更新评测机 Web 地址”重建连接；改页面配置本身不会修改运行中的容器。

## 备份和启用备用

在“状态与主备切换”查看独立的服务器与服务状态，或选择节点进行维护。

- 服务器状态表示 SSH 是否连接成功；认证失败或连接超时显示 SSH 不可用，不能据此断言主机已关机。
- 服务状态分为未部署、备用未启动、Docker 未运行、容器停止/缺失、容器运行但业务异常、业务检查正常。Web 验证登录与样式；评测机验证新心跳。
- 检测发现已托管且已部署的启用节点服务停止时，点击卡片上的“一键启动”。只启动已有容器，保留数据与配置；完成后自动复查。容器缺失需要重新部署，不会假报成功。
- Docker 停止时会启动主机 Docker 服务；同机其他容器也可能按原重启策略恢复。备用节点通过“启用所选备用”执行接入流程。
- 备份与切换等停机操作需要核对维护时间；检测和启动无需重复勾选维护确认。

- 评测机备用：启用后创建/验证专用评测账号，启动容器，确认新心跳。
- Web 备份：要求评测队列为空，暂停站点和关联评测机，冷备份完整 `data`，下载到 Windows，校验 SHA256，然后恢复原站。
- Web 备用启用：要求源站在线、目标无业务数据，比较实际镜像 ID，检查空间，再冷备份、恢复数据库和题库到目标、核对登录/CSS/关键数据数量、重绑评测机。
- 迁移失败：尝试停止目标、恢复旧站和原评测机连接。原始数据和 Windows 快照均保留；回滚失败会明确记录，需要按日志人工处理。
- 旧站切换后保持停止并保留旧数据，不会自动成为实时同步副本。再次迁移应使用新的空白备用目录，不能覆盖旧数据直接往回切。

这是受控停机迁移，不是双主、实时复制或源站失联后的自动故障切换。完整步骤见 [迁移与恢复](docs/03-迁移与恢复.md)。

## 开发版启动

源码在 `source` 目录。Windows Python 3.12：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe server.py
```

HTML 不能单独双击完成 SSH 部署，必须通过本地执行程序启动。界面没有外部 CDN 或字体依赖。

## 下载版本核对（v1.3）

“下载到本地”读取部署程序 Release（例如 2.0.271），不是 OJ 镜像标签（例如 2.0.281-exp）。文件保存到 Windows 工具资料目录的 tools 缓存，以 SHA256 命名；界面显示原始附件名称、下载版本、来源网址和实际缓存路径。它不会自动出现在浏览器的下载文件夹。上传到服务器时仍使用所选缓存程序。

更改 Release 后若当前已下载文件版本不一致，会显示提示并阻止部署；请重新下载或改回版本。旧版缓存、手动上传文件的版本未知，会如实标注。下载失败保留上一份文件，但不会当成本次下载成功；不存在的 Release 不自动回退到其他版本。

## 当前实际使用版本（v1.4）

Linux 部署程序标题下方突出显示“当前部署将使用”的文件版本。修改 Release 输入不会改变已选文件；版本不一致时会显示原文件版本和暂不能部署提示。未选择文件、手动上传或旧缓存版本未知也会明确标注。

## 独立 SSH 密钥管理（v1.5）

侧栏“SSH 密钥管理”可在没有 OJ 节点、没有部署程序时独立使用：

1. 添加连接，填写本地私钥文件名、服务器 IP、SSH 登录账号、端口及首次登录密码。账号必须已经存在于服务器。
2. 保存连接，勾选记录。“生成 / 复用本地密钥”只操作 Windows 文件；已有密钥不会重新生成。
3. 点击“配置服务器公钥并验证”：自动在本地生成或复用私钥，通过登录密码或已有授权连接，把公钥追加到对应用户的 `~/.ssh/authorized_keys`，然后断开并用纯私钥重新登录验证。不会执行 sudo、安装 Docker 或启动 OJ。
4. “测试纯密钥登录”不使用登录密码，也不修改服务器公钥。
5. 修改 IP、登录账号或端口后保存；使用同一私钥名的已保存部署节点会同步更新。点击“保存并同步本机 SSH”时，已有私钥的连接会立即同步到 Windows `~/.ssh/config`，`ssh 私钥文件名` 使用新 IP、账号和端口。保留同一私钥，保存不连接服务器、不改 known_hosts，也不代表新账号已授权。没有本地私钥的连接只保存记录。批量部署的公钥配置步骤也会生成别名。工具修改前会备份 config，更新自己管理的别名或引用同一私钥的同名别名；引用其他密钥的同名连接会提示冲突并保留原配置。不自动创建或重命名 Linux 账号。若改成另一个用户，需为新用户重新配置公钥。

已有 `web` / `pcj` 前缀密钥：点击“扫描 web / pcj 前缀密钥”，核对 Windows `.ssh/config` 中的地址、账号、文件和公钥指纹，选择后确认导入。密钥复制到 `%LOCALAPPDATA%\CSGOJDeploy\keys`，原文件保留。同名但内容不同的私钥会拒绝覆盖；既有工具连接保留原 IP/账号，需要修改时直接编辑表格。

私钥始终留在 Windows，仅公钥传到对应服务器。连接密码保存在 Windows DPAPI 加密的 `ssh-connections.dpapi`，不进入 ZIP。工具同时检查 Windows `.ssh/known_hosts` 和自己的指纹记录；指纹变化会停止连接，不自动删除旧记录或信任新指纹。

先保存节点页尚未保存的修改，再使用 SSH 模块；返回节点页会显示已保存并同步的连接信息。只有本工具管理的部署才可执行启动/备份/切换，导入 SSH 密钥不会自动接管既有站点。

## 每台评测机调整 pods（v1.5）

新节点在编辑页填写 pods；已准备节点在“节点配置 → 编辑”修改“目标 pods”并保存。当前配置数不会被提前改成目标值。到“状态与主备切换”选择该评测机，勾选维护确认，点击“应用评测机 pods”。

- 先检查版本、主机资源及评测队列；请安排无新提交的维护时段。按官方部署程序每 pod 4 核 / 4 GB 并留系统余量检查；6 核主机不能设为 2 pods。
- 启用节点：移除该机旧评测容器，按目标数调用已上传的官方程序重建，检查所有预期容器运行和 Web 评测账号新心跳；成功后更新工具中的当前数量。失败会尝试恢复原数量，恢复失败会明确记录，需人工检查。
- 备用节点：只更新已校验资源的计划数量，保持服务关闭，不接入 Web。
- 官方多个 pod 复用同一评测账号，Web 的评测账号数量不会随 pods 增加。Web 心跳正常且预期数量容器运行，是本工具的启动验收；不等于已对每个 pod 完成真实 AC/WA 评测。
- 本次只调整 pods，不同时升级镜像。不要修改全局镜像标签后把它作为升级入口。

SSH 扫描匹配 `web`、`pcj` 前缀（不区分大小写），不限制 `-exp` 后缀。例如 `web01`、`web-prod`、`web-exp`、`pcj-backup` 都可扫描；只有私钥文件没有 SSH 地址记录时，可在导入预览补填 IP、用户、端口。

## 更新已部署节点

在“状态与主备切换”选择 Web 或评测机，查询可用版本、填写目标标签，先检查并缓存镜像，再在维护时段点击“更新所选节点”。同名 exp 标签也会重新拉取并比较实际镜像。Web 保留数据库、管理员和各项口令，以及原 MySQL/phpMyAdmin/Nginx 容器；只更新 OJ 应用容器。评测机保留账号、pods 与绑定 Web。备用仅缓存。详见 [镜像更新与恢复](docs/06-镜像更新.md)。

此入口用于本工具已有的托管节点，不会凭 IP 自动接管此前手动部署的站点。没有后台定时升级。

### 导出业务账号与口令

在“部署资料”点击“一键导出全部 TXT”，或勾选节点后点击“导出勾选节点 TXT”。Web 包含管理员账号、保存的管理员密码、MySQL root / 数据库业务 / phpMyAdmin 页面三项口令；评测机包含绑定 Web、评测账号和密码。文件保存到浏览器下载目录。

只读取本机已保存配置，不连接服务器、不生成密码、不改配置。未保存的口令标注缺失；在 OJ 修改过的管理员密码可能与本机旧记录不同。单选评测机不会附带未选中 Web 的口令。未登记为部署节点的独立 SSH 连接不包含业务账号。TXT 含明文业务口令，不含 SSH/sudo 密码或私钥。

## 数据库存储与 SSD（v1.9.0）

- 节点配置 → 添加 Web → **初始化数据库目录**：留空沿用项目 `data/var/mysql/mysql_data`，也可填写已挂载 SSD 下的空目录，例如 `/data-ssd/mysql/ccpc`。只在第一次初始化时使用；已部署节点不能直接改此字段。
- 状态与主备切换 → 选择 Web → **数据库存储 → 检测实际存储位置**：显示项目、数据库、代码、题库、Docker 的设备、挂载点和可用空间。已接管项目会记录磁盘 UUID；后续操作会核对原挂载，防止 SSD 掉盘后误写系统盘。
- 已有数据迁移：填写目标 → 检查迁移目标 → 勾选维护确认 → 迁移数据库 → 弹窗二次确认。先暂停站点和关联评测机，正常停止 MySQL，再用 rsync 保留属主、权限、硬链接与扩展属性复制并逐文件校验。保持原容器、口令及官方路径，通过 bind 挂载使用新目录。
- 目标必须是空目录、在本地 ext4/xfs/btrfs 文件系统上，不能位于原项目内部。SSD 需事先按 UUID 配置开机挂载，不会格式化磁盘。迁移要求已有 rsync（`sudo apt-get install rsync`）。
- 写入独立的 Docker systemd 挂载依赖；重启时磁盘未挂载会阻止 Docker 服务启动（会影响该主机其他 Docker 容器）。不重启 Docker 守护进程，不改变其镜像存储目录。
- 原数据库文件保留；切换前失败会尝试恢复原挂载，已开放写入后不自动回退。意外中断使用 **恢复未完成数据库迁移**。目标残留副本不会自动删除，重试请使用新的空目录。
- 数据库分盘后，备份仍包含数据库，镜像更新回滚会保留数据库挂载并恢复内容。迁移记录在服务器项目 `private/database-migration-*.json`。


## v1.9.1 自动镜像下载

点击“拉取并保存到本地”后，由工具直接通过 Registry V2 下载所选版本的 Linux amd64 镜像，不依赖 Docker Desktop 的代理设置。按优先源依次回退，自动使用系统代理、已运行的本机 VPN 代理监听端口或直连；不会修改系统代理和 Docker 永久配置。每层失败自动重试，已校验层缓存于 images/blobs 供重试复用。清单、压缩层 SHA256 和解压后的 diff_id 均校验后生成标准 Docker 归档，登记至同一 images/catalog.json，刷新本地缓存即可查看和分发。归档下载不请求额外 referrers 元数据；不下载或验证签名证明。代理地址和令牌不会写入任务日志。


## v1.9.2 下载与加载校验

下载最多四层并行，并按 SHA256 复用下载层、已有归档和正在运行的本机 Docker 镜像层。每次仍重新读取远端清单，避免同名 exp 标签更新后误用旧内容。只在本机导出 Docker 缓存，不自动启动 Docker，也不连接远程 Docker。

自动代理发现会验证 HTTP CONNECT，并排除 53000 控制端口。镜像源设置只用于本次下载，不写入永久 Docker 配置。打开工作台时三项依赖默认不勾选，初始化需要时手动勾选。

containerd 返回父索引 ID 时，工具读取 docker save 流中的实际配置摘要并核对全部文件系统层和 Linux amd64 平台，避免同一镜像被误判为加载失败。
