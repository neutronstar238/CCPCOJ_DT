# 断网准备与排障

## 联网时先准备

备用节点执行准备即可下载所需资源。启用节点完成部署后也已缓存镜像。

- Windows 留有官方部署程序、私钥、配置和业务口令导出。
- 每台主机都有 Docker、Python 3、SSH 和对应镜像。
- Web 除 OJ Web 镜像，还需要 MySQL、Nginx、phpMyAdmin；不能只下载一个 OJ 镜像。
- “状态与主备切换”中的全部/单节点检测能显示 SSH、缓存和业务状态。
- 断外网后 IP 可以变化，但先保留节点名和密钥名，更新 IP 后检查连接。Web IP 改变时重绑关联评测机。

已有标签默认复用缓存，不自动拉取同名 exp 标签的新内容。要升级到重新推送的同名标签，需在维护窗口由部署人员明确更新镜像并重新验证；Web 迁移时不能混用不同实际镜像。

备用测试容器使用 `--network none`，运行完即删除。该模式不会创建 OJ 账号、启动站点或接入评测队列。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| SSH 超时 | 检查 IP、端口、路由、防火墙和 ssh 服务 |
| Authentication failed | 检查 SSH 用户/密码；已有本工具密钥时确认对应公钥仍在服务器 |
| SSH host key mismatch | 独立确认服务器指纹，确认重装或换机后再更新本工具 known_hosts |
| sudo 提权失败 | 密钥只负责 SSH 登录；填写该账号 sudo 密码，并确认账号在 sudo 组 |
| su 提权失败 | root 密码可能未启用；Ubuntu 通常使用 sudo |
| 下载工具 404 | Release 版本与镜像 tag 不同；不要用 `2.0.281-exp` 去猜工具下载地址，可直接选择已有程序 |
| 镜像下载超时 | 在版本与镜像分发模块选择腾讯云或自定义 HTTPS 镜像源；仅在 Windows 拉取，apt 软件源仍独立 |
| 主机 CPU 不足 | 官方工具预留 2 核、每 pod 4 核；6 核只能 1 pod |
| 无性能模式接口 | 虚拟机/硬件没有 powerprofiles/cpufreq，日志会明确跳过 |
| 已有目录/容器被拒绝 | 工具只管理自己创建的节点；选择新目录，不能用这个按钮覆盖已有站点 |
| 容器运行但心跳失败 | 查看评测日志，检查 Web 内网地址、账号口令、服务连通性；工具不会据此报告评测成功 |
| 备用有运行容器 | 状态检查会报告异常，先确认是否被手动启动；不要在两个主站同时办赛 |
| 迁移后验收失败 | 查看回滚日志，检查原 Web 与全部评测机；不要删除旧数据和快照 |

## 手动核对

```bash
sudo docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
sudo docker image ls
sudo docker logs --tail 100 judge-<节点名称>
sudo docker logs --tail 100 php-<站点标识>
sudo systemctl get-default
```

v1.7 不再修改服务器的 Docker 镜像源。以下仅供旧版本恢复参考：旧版 Docker 镜像配置备份在服务器 `<项目>/private/docker-daemon-before.json`。如果电脑强制关机或 SSH 断开导致流程中断，请检查 `/etc/docker/daemon.json` 和 `docker info` 的 Registry Mirrors，不能只依据配置文件中删掉了字段就认定内存里的镜像源已清空。

普通“停止”在节点边界生效。迁移关键阶段会完成恢复/回滚再结束，避免取消到一半丢失切换状态。远程长命令超时不代表远端进程一定结束，先查看服务器和日志再重试。

工具不会自动开放整个防火墙。比赛内网应能访问 SSH、Web 和必要的 phpMyAdmin 端口；数据库端口默认不向外开放。
