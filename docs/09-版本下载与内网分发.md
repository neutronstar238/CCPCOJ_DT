# 版本下载与内网分发（v1.9.2）

在左侧打开 **版本与镜像分发**。各项功能独立执行，不需要先连接服务器查询版本。

## 部署程序

1. 点击“查询全部 Release”。来源是 `SZTU-ACM/CCPCOJ-2` 的 GitHub Release API，逐页读取。
2. 选择 Release 标签和 Linux amd64 附件，点击“下载并选用部署程序”。标签可以包含 `-exp`；附件名称使用仓库实际返回值。
3. 附件先存入 Windows 的 `tools` 目录；执行部署时再通过 SSH 文件传输上传。下载失败保留之前的选择，不回退到其他版本。

Release 与 Docker 标签是两套发布记录：镜像已有新版本，不代表仓库发布了同版本部署程序。缺少 Release 时仍可在节点配置页选择开发者提供的本地 Linux 文件。新版离线流程要求部署程序的 `up` 和 `judge` 支持 `--no-pull`；不支持会明确拒绝执行。

## 下载镜像

1. 选择 Web、评测机或两者。点击“查询所有镜像版本”会逐页查询 Docker Hub 标签，查询失败不会伪装成完整列表。选择两者时列表来自 Web；下载时分别验证两类镜像确实存在。
2. 选择或输入目标标签；同名 exp 再次下载会拉取当时仓库的内容。
3. 选择本次下载源：

| 来源 | 行为 |
| --- | --- |
| 部署程序默认腾讯云 | `ccr.ccs.tencentyun.com/csgrandeur/`；已从用户提供的 2.0.287-exp2 部署程序核对 |
| Docker Hub | 使用官方镜像名，由工具直接连接 Docker Hub Registry |
| 自定义源 | 输入 HTTPS 域名，可带端口。例如 `mirror.example`。代理路径保留 `csgrandeur/`，官方依赖使用 `library/` |

此选择不修改本机或服务器的 `daemon.json`。按所选源优先，失败后自动尝试腾讯云和 Docker Hub（去重），始终保持指定版本。工具自动使用系统代理、已运行的本机 VPN 代理或直连；每次失败原因和实际成功源均显示在日志中。

4. 全新 Web 部署保留“包含依赖”勾选，会同时准备 MySQL 8.0.32、Nginx 1.29.7-alpine、phpMyAdmin 5.2.3。这是当前适配的部署程序依赖组合；新部署程序变更依赖时工具会拒绝盲目部署。
5. 点击“拉取并保存到本地”。无需 Docker Desktop。工具通过 Registry V2 获取 Linux amd64 清单，下载并校验各层 SHA256 与解压 diff_id，再生成兼容 Docker Engine 和 containerd 的归档。日志显示层数、MB、百分比和校验/归档阶段。网络中断自动重试，已校验的层保留在 images/blobs，下次重试复用。

## 使用现有镜像文件

可以使用 `docker save` 输出的 `.tar` 或 `.tar.gz`，包括一个文件内多个标签。不能使用 `docker export`，也不能把普通文件改名成 tar。

```powershell
docker save --output E:\images\judge.tar csgrandeur/ccpcoj-judge2:<版本>
```

点击“选择并导入镜像归档”，或填写本机完整路径再点击按钮。大文件由本地程序直接分块读取，不经过浏览器 40 MB 上传接口。工具复制到缓存并检查实际标签、平台及 SHA256，不靠文件名猜版本。

“选择本地已缓存版本”可离线选择版本。多个文件包含同名 exp 标签时，点击对应行的“选用此归档”；列表的“当前选用”标记决定部署和更新使用哪份。同名文件不覆盖其他内容，归档以 SHA256 命名。

## 分发与部署

勾选目标节点后点击“分发到勾选节点”。默认不勾选任何服务器。工具根据节点类型和上方版本匹配本地归档，通过 SSH 上传、核对 SHA256、执行 `docker load` 并核对镜像内容 ID。支持传统 Docker config ID 和新版 containerd/OCI manifest ID。上传会显示百分比；解压期间显示当前阶段。

分发本身不停止或重建业务容器，不登记新的评测机、不切换备用。已有 Docker 未启动时会启动 Docker 服务；新主机缺少 Docker 时仍需联网安装 apt 软件包。镜像归档不等于完整的离线操作系统安装包。

准备好缓存后，也可以直接执行“批量部署”或“更新所选节点”，这两条路径自动从本地分发。官方部署传入 `--no-pull`，服务器不再临时下载 Docker 镜像。

更新 Web 时只选择并分发 Web 应用镜像，沿用原数据库、phpMyAdmin、Nginx 容器、挂载和口令。现有的维护确认、备份、登录验证和更新失败恢复保持不变。评测机保留账号和 pods 设置。

## 文件位置

默认缓存目录为 `%LOCALAPPDATA%\CSGOJDeploy\images`，文件表显示完整路径。可将 tar 复制到另一台 Windows，在另一工作台导入；不要复制整个凭据目录。镜像归档和部署程序均不嵌入发布 ZIP，避免分发包过大。

## 历史验证（v1.7）

- 自动化回归覆盖全部标签分页、实际 Release 附件选择、缺失版本不回退、归档平台/路径/层检查、同名 exp 选择、文件篡改拦截、只分发不重建。
- 浏览器覆盖源选择、异步查询、归档导入、本地版本选择、空目标不执行和窄屏布局。
- 实际下载官方 2.0.271 Release 附件，并验证 ELF 与大小。
- 将约 632 MB 的 2.0.287-exp 评测归档通过真实 SSH 传入独立 WSL Ubuntu 24.04，docker load 后校验通过，前后业务容器清单保持一致。
- 本次未在比赛服务器执行升级。当前 Windows Docker Desktop 引擎未运行；镜像在线 pull/save 路径仍需要启动本机 Linux 引擎后实机验收，不把归档分发通过等同于该路径通过。

实现依据：[GitHub Release API](https://docs.github.com/en/rest/releases/releases)、[Docker image save](https://docs.docker.com/reference/cli/docker/image/save/)。

下载优化：最多四层并发；复用已经校验的下载层、旧归档、正在运行的本机 Docker 缓存。默认不包含三个数据库/入口依赖，仅全新初始化时手动勾选。控制端口 53000 不参与代理发现。
