# 本地部署（v1.10.0）

入口位于“部署资料”后、“使用说明”前。该页只管理本机 WSL 内的实例，远程服务器仍在原来的批量更新页管理。

## 准备与首次启动

1. 安装 WSL 2 Ubuntu 24.04 x86_64。选择已安装的发行版，填写其中的 Linux 部署根目录，默认 `/srv/csgoj-local`。Web 与评测数据分别放在 `web`、`judge` 子目录。数据库建议使用发行版 Linux 文件系统；发行版虚拟磁盘在 Windows 哪块盘上，由 Windows WSL 管理，不在此页面搬迁已有虚拟磁盘。
2. 该发行版需要 systemd。使用发行版自己的 Docker；若打开了 Docker Desktop 对此发行版的集成，先关闭该集成。工具拒绝把 Linux 数据路径交给 Docker Desktop 的另一套文件系统。缺少 Docker 时，首次部署会通过 apt 安装，系统软件包下载仍需要外网。
3. 在“版本与镜像分发”选好 Linux 部署程序，下载或导入镜像归档。本地部署与内网分发共用同一个 `images/catalog.json` 和 `tools` 缓存。首次 Web 需要 Web、MySQL、Nginx、phpMyAdmin；评测机需要 judge 镜像。版本输入没有内置默认值。
4. 配置 Web 端口、管理员、评测 pods。评测机可连接本地 Web（自动注册评测账号），或指定外部 Web 地址及该站点已有的评测账号密码。外部 Web 模式不会自动注册账号或修改外部站点。
5. 选择本地 Web、PCJ 或两者，分别填写目标版本，核对并确认后点击“部署 / 更新所选服务”。同时选择时先部署 Web。已有数据或不完整容器不会被当作空白初始化。

字段修改后失焦即保存到 Windows 当前用户的 DPAPI 文件 `local-deploy.dpapi`，与远程节点的 `config.dpapi` 分开。首次部署后可展开“本地 Web 登录资料”查看初始管理员账号密码。此资料含口令，应妥善保管；站点后续自行改密不会自动同步。

## 检测、启动和更新

- “获取本地版本与状态”读取 WSL 中的运行版本、镜像标签和服务状态；不勾选时检测两种本地服务。评测机显示实际运行 pods 和配置 pods。
- 勾选已部署的服务，点击“一键开启所选服务”可启动已有容器并检查。本地 Web 检查登录和 CSS，本地 Web 绑定的评测机检查新心跳；外部 Web 模式只验证容器运行，心跳需在外部站点核对。
- 服务名称下显示最近检测的运行状态、检测时间；长版本列表自动换行。未检测、已关闭、运行中和部分运行分别显示，评测机同时显示实际运行 / 配置 pods。
- “关闭所选服务”只停止勾选的本地容器，保留配置、数据库、镜像及容器本身；同时勾选时先停 PCJ 再停 Web。不关闭 WSL、Docker 或其他服务。只关闭 Web 时，绑定它的 PCJ 暂时无法评测。关闭后再次获取状态显示“已关闭”，可用一键开启恢复。
- 修改目标版本，确认后更新。WSL 已有镜像直接复用，缺少镜像才复制 Windows 缓存并校验后 load。更新 Web 会保留 SQL 等基础容器、业务口令、数据和挂载，不重新初始化数据库。
- 为避免误指向其他数据，已准备实例的发行版、目录、端口及身份字段不能直接修改。目标版本仍可修改。未完成的更新可通过恢复按钮处理，每次恢复仅选择一个服务并确认。
- 本地服务启动后使用一个带发行版锁的 WSL 保活进程，避免只有 systemd 后台服务时 WSL 空闲退出。关闭工作台不会主动停止本地服务。如需完全关闭发行版，执行 `wsl --terminate 发行版名称`；再次一键开启会重新启动并检查服务。
- 本地评测机通过 Docker 网桥地址访问同机 Web，避免依赖重启后可能变化的 WSL 网卡 IP。工作台检测时重新获取 WSL IP。

## 批量选择与 pods

远程“批量更新”页新增“全选 PCJ 评测机”“全选 Web”“清空选择”。两类全选是追加勾选，不会清除其他已选节点，选择变化会清除维护确认。状态页 pods 来源于 Docker 实际容器列表；未检测显示“未检测”，不会用配置数冒充运行数。
