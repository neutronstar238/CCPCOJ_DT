# v1.6 全新 Ubuntu 环境验收

测试日期：2026-10-17。使用 Windows 上的本工具源码，通过真实 SSH / SFTP 操作独立 WSL2 Ubuntu；不是用模拟 Docker 返回值代替部署。

## 环境和版本

- 新建发行版：`CSGOJ-Console-QA-20261017`，Ubuntu 24.04.4 LTS 官方 WSL rootfs，校验官方 SHA256 后导入。
- rootfs SHA256：`9b2f7730dc68227dd04a9f3e5eab86ad85caf556b8606ad94f1f29ff5c4fd3f5`。
- 全新用户、独立配置目录与随机测试口令，没有复用现场数据库或私钥。
- 官方 Linux 部署程序：`2.0.271`；Docker 由本工具安装，版本 `29.1.3`。
- 初始 Web / judge 镜像：`2.0.277-exp`；更新目标：`2.0.282-exp`。
- WSL 分配 16 核、约 48 GB 内存；题目为正常 A+B，提交正确和错误的 C++ 程序。

测试同时修复了本工具的三个问题：首次管理员创建后自动登录导致再次登录校验失败；无挂载的 phpMyAdmin 被错误判为不属于本站；Docker 重启返回的挂载列表顺序改变导致更新校验误报。另将启动次序明确为数据库、phpMyAdmin、PHP、Nginx。

## 验收边界

真实 WSL 测试验证了本工具管理的节点。后续已补充官方部署接管流程；原现场服务器需填入原配置和凭据，通过“检查已有部署”并确认接管后才能更新，详见镜像更新指南。

已测试 Web 更新前冷备份及同机回退；尚未完成两台独立物理主机间的比赛数据迁移、掉电恢复和各种 PAM/su 配置组合。WSL 不能证明真实评测机的 CPU 性能模式效果。

测试网络需要 Windows 转发代理才能访问镜像仓库，临时配置仅放在独立测试发行版中。正式部署按现场网络填写镜像源。WSL 中多个发行版可能共享网络规则，本次保持其他发行版停止并只操作新建测试环境。

所有运行口令、私钥、数据库快照及实际服务器资料均不进入分发 ZIP。包内自动化检查的重跑命令见 [验证记录](05-验证记录.md)。

发布包不附带历史环境截图，当前隔离环境验收见 verification/v1.10.3-ui-races.md。
