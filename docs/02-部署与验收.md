# Web 与评测机部署

## Web

添加 Web 节点，填写主机、项目目录、站点标识、两个端口和管理员账号。项目目录默认 `/home/ccpc00/cpc`，Web 数据放在其 `data` 子目录。

后台调用官方工具的命令结构如下；口令由程序传入，不需要手工拼接：

```bash
sudo /home/ccpc00/cpc/csgoj-deploy up --noninteractive \
  --path-data /home/ccpc00/cpc/data \
  --name-prefix <站点标识> \
  --nginx-ranges '<Web端口>-<Web端口>,<管理端口>-<管理端口>' \
  --site '<站点标识>:<Web端口>:cpcsys:cpc' \
  --port-myadmin <管理端口> --port-db 0 \
  --sql-root '<随机数据库root口令>' \
  --sql-user-pass '<随机业务口令>' \
  --myadmin-pass '<随机phpMyAdmin口令>' \
  --no-redis --no-dev --no-build --csgoj-version <镜像标签>
```

默认网站地址为 `http://<Web服务器IP>:20080`。初始化只在页面确认为未初始化时执行；之后使用填写的管理员口令登录验证。

目前适配的工具依赖镜像为 `mysql:8.0.32`、`nginx:1.29.7-alpine`、`phpmyadmin:5.2.3`。上传的工具中不再包含这些引用时，程序会停止，要求检查新版依赖后更新适配，避免备用机缓存错误依赖。

## 评测机

添加任意数量的评测机节点，默认命名 pcj01、pcj02……。每台选一个启用的 Web。

评测容器名称与 OJ 内的评测账号不是同一个字段。节点可叫 pcj01，OJ 账号自动分配 j1、j2……，也可手动指定，例如 pj01。官方账号要求 1–2 位小写字母后接 1–2 位数字，单 Web 最多 99 个评测账号。

工具在创建账号前检查是否已有同名用户，不会覆盖普通用户或口令不同的既有评测账号。

```bash
sudo /home/ccpc00/cpc/csgoj-deploy judge \
  --server-url http://<Web内网IP>:<Web端口> \
  --username <评测账号> --password '<随机评测口令>' \
  --oj-name <节点名称> --pods 1 \
  --path-data /home/ccpc00/cpc/data \
  --csgoj-version <镜像标签>
```

官方评测工具每 pod 固定分配 4 核，另预留 2 核。6 核机器开 1 pod；2 pod 至少 10 核，不能只看“内存足够”就开启。界面允许填写 pods，但会在远端按实际资源检查，不会伪造 CPU 数量。

正式重建已部署评测容器使用官方 `judge --oj-name <节点> --remove-all` 后重新部署，只针对该托管节点，不操作其他容器。

## 验收范围

工具检查：

1. 所有目标容器存在并运行。
2. Web 能登录管理员账号，比赛页面 CSS 返回正确资源而非 HTML 错误页。
3. 评测账号的 OJ 心跳在启动后有新变化，避免仅凭容器 running 判断成功。
4. 备用只检查缓存镜像和离线 PHP/编译运行环境，没有向 Web 注册评测账号。

开赛前仍要在 OJ 创建一道题和测试比赛，以选手账号提交 AC、WA、CE、TLE 等样例。工具本次没有自动创建测试比赛、测试题或大量选手账号；它也不会把缓存镜像检查宣称为完成了整场比赛验收。
