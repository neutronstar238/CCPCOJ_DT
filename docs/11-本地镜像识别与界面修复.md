# v1.10.3 本地镜像识别与界面修复

在“版本与镜像分发 → 已有本地镜像”点击“识别已有本地镜像”，读取本工具缓存、包旁 images、下载目录、桌面以及 Documents/Codex 中的镜像归档，同时读取本机 Docker Desktop Linux 引擎的已有镜像。扫描最多 6 层目录、300 个候选归档，不跟随目录符号链接。不会启动 Docker、下载镜像或部署服务。

识别依据是归档清单、真实镜像标签和 Linux amd64 平台，不依赖文件名。版本保持留空，直到用户明确选择；指定目标版本后，唯一匹配归档可以自动填入路径。多个匹配项需要自行选择。明确选择应用镜像时，同步其真实版本和 Web / 评测机类型。切换版本会清除旧文件路径。

- 磁盘归档：选择结果后，点击“选择并导入镜像归档”，校验并登记到统一缓存。
- Docker 已有镜像：选择后点击“导出所选 Docker 镜像并导入缓存”。导出前后检查内容标识和平台；已选缓存内容相同且 SHA256 校验通过时直接复用。
- Docker 未启动：显示不可用原因，磁盘归档仍可识别、导入。不会把“引擎不可用”显示成“没有镜像”。

本版修复 WEB-01 至 WEB-09：节点完成与自动保存冲突、SSH 勾选丢失、快速任务元数据未更新、空导入选择、缓存路径与版本不一致、保存覆盖新目标和光标、跨页冲突操作、结果应用期间过早解除忙碌、手机长路径撑宽页面。

所有页面共用任务锁，正在应用终态结果时继续禁用冲突控件，导航和任务停止按钮可用。状态轮询串行，缓存刷新按请求顺序应用。节点完整保存串行，保留保存期间新输入的版本和设置。

另外，WSL 执行器和保活进程使用资料目录作为工作目录，避免后续启动的子进程因为继承旧安装目录而阻止移动或删除工具文件夹。已经运行的旧版进程不受新 ZIP 影响。

实现参考用户提供的“自动识别副本”源码，未运行其中的程序，未合入其额外 Docker Desktop 部署管理。现有本地 WSL 部署保持原方式。

开发验证：Python 使用 `python -m unittest discover -s tests -p "test_*.py"`；前端使用 `npm install` 后 `npm test`。Node/jsdom 仅用于开发测试，不是发布版运行依赖。`tests/ui_fixture.py` 是本机内存测试服务，模拟任务，不运行 SSH 或 Docker。
