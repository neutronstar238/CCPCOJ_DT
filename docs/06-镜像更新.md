# Web 与评测机镜像更新

适用对象：本工具已创建的节点，或已通过检查并确认接管的官方部署节点。请勿把“批量部署”当作已有站点升级按钮。

## 接管已有官方部署

先在“节点配置”保存原项目目录、站点标识、端口、SSH 连接及原业务凭据。Web 填原管理员与三个业务口令；评测机填原评测账号、密码、Web 地址和 pods。

在“状态与主备切换”选择节点，点击“检查已有部署”。检查会核对实际容器、镜像、挂载、账号配置和 Web 登录或评测心跳；通过后点击“确认接管所选节点”。接管仅记录现有部署，不重建容器、不重置口令。检查后修改过节点配置时，需重新检查。

只填写相同 IP 不足以接管；路径、原凭据或部署结构不匹配时应先核对，不要初始化原站点。

## 使用步骤

1. 打开“状态与主备切换”，选择操作节点。
2. 点击“查询可用版本”。从镜像仓库获取近期发布的标签；Web 和评测机分别查询。`-exp` 是实验镜像，正式版与实验版请自行选择。
3. 填写“本次目标镜像标签”，例如 `2.0.282-exp`。
4. 先在“版本与镜像分发”下载或导入并选用目标归档，再点击“分发并检查目标镜像”。工具从 Windows 经 SSH 分发该标签并执行断网容器自检；比较镜像 ID，而非只比较标签字符串，因此同一个 exp 标签重新发布也能识别。这个动作不停止业务。
5. 安排停止新提交的维护时段，勾选维护确认，点击“更新所选节点”。工具只更新所选节点，不连带升级其他节点。备用节点只刷新镜像缓存，不启动业务或注册评测账号。
6. 等待日志中的“完成”，检查状态卡中的实际部署版本、Web 登录/样式或评测心跳。更新后再提交一道已知正确和一道已知错误的程序验收。

## 保留什么，更新什么

| 项目 | Web 更新行为 |
|---|---|
| PHP / OJ 应用容器 | 使用目标镜像重建，保留原挂载、网络、运行参数与业务环境变量；静态资源同步更新 |
| MySQL | 保留原容器、镜像、数据目录和口令；冷备份期间暂时停止，之后启动 |
| phpMyAdmin | 保留原容器、镜像与配置，原页面口令文件不重写 |
| Nginx | 保留原容器、镜像与配置；应用恢复后启动 |
| 管理员与其他账户 | 不再次初始化、不修改密码；用原管理员密码登录验证 |
| 题库、比赛、提交 | 原卷复用；更新前冷备份，更新后核对记录数量 |
| 关联评测机 | Web 更新期间暂停，更新完成后启动原容器；版本不跟随变化 |

评测机更新保留原账号、密码、Web 地址、pods、CPU/内存限制和挂载，只替换应用镜像。不会额外创建一个新评测账号。

“PHP 应用容器”与“phpMyAdmin”是两个不同组件。代码在 PHP 应用镜像里，升级代码需要替换它；它连接的数据库和业务凭据保持不变。

## 备份与失败恢复

Web 更新前会把一致性冷备份保存到 Windows 工具资料目录 `backups`，远端项目 `private` 内也会保留恢复归档。备份含数据库和业务数据，请按部署凭据同等级保管。需要预留归档与恢复空间。

应用替换前写入远端恢复记录。替换或验收失败时，工具尝试恢复原镜像和更新前数据，再启动原服务。失败版本的数据目录另存为 `data.failed-*`，不会当场删除。不要在更新验收期间允许选手提交；恢复更新前快照会回到备份时刻。

若 Windows 窗口意外关闭、SSH 中断或自动恢复失败，重新启动工具、选择原节点，勾选维护确认后点击“恢复未完成更新”。读取的是服务器上留下的恢复记录，不依赖浏览器内存。恢复失败时保持现场，查看日志及备份，不要再次初始化站点。

更新已经提交后，若关联评测机网络不通，界面会报后续检查失败；此时不会回退已重新开放的站点数据库。修复连接后检测节点或一键启动服务。

## 实现边界

首次部署仍上传并运行所选官方 Linux 部署程序。更新使用本工具的专用容器替换流程，从实际运行容器读取配置并固定目标镜像 ID，不重复执行会改写 SQL/phpMyAdmin 配置的全套 `up`。原官方可执行文件不被修改。

不会后台定时升级。每次由部署者选择目标标签、节点并发起更新。镜像仓库接口不可用时，不宣称“已经最新”；可以填写已知标签直接检查拉取。

第三方镜像自身可能执行数据库结构迁移，本工具不能保证任意未来版本互相兼容，因此保留升级前快照，并在验收成功前保留恢复记录。正式比赛前仍须完成正常提交验收。
