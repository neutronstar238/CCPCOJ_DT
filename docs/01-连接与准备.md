# 连接与准备

对象是已安装的 Ubuntu 24.04 LTS x86_64。Windows 工具包通过 SSH 与 SFTP 管理它。

## 服务器先有 SSH

如果目前已经可以 `ssh ccpc00@<IP>`，这一节不用执行。

否则在服务器本地终端运行：

```bash
sudo apt-get update
sudo apt-get install -y openssh-server python3
sudo systemctl enable --now ssh
hostname -I
```

记录服务器内网 IP。Windows 先确认路由和 SSH 端口：

```powershell
Test-NetConnection <服务器IP> -Port 22
```

SSH 必须至少允许一次有效密码登录，或已安装本工具资料目录里对应的公钥。工具不会绕过远端认证设置。

## 三种提权方式

| 模式 | SSH 登录 | 提权密码 |
| --- | --- | --- |
| sudo | `ccpc00` 等普通用户 | 该用户自己的 sudo 密码；留空使用 SSH 登录密码 |
| su | 普通用户 | root 密码；目标机必须允许 su 且 root 密码有效 |
| 直接 root | `root` | 不再调用 sudo/su；前提是服务器允许 root SSH 登录 |

Ubuntu 默认 root 可能没有可用密码，通常选择 sudo。把 SSH 公钥安装好，不会自动得到 sudo 权限。工具也不会写入免密 sudo 规则。

## 公私钥

工具在 Windows 资料目录 `keys` 下生成 Ed25519 私钥。名称由页面填写。重用同一名称时不会重新生成密钥。

远端只追加公钥，保留已存在的其他管理员公钥。`.ssh` 为 700，`authorized_keys` 为 600。首次主机指纹写入本机 `known_hosts` 并在日志显示；之后发现同 IP 的主机密钥变化会中止。服务器重装后，请先独立确认新的 SSH 指纹，再手工更新这份 known_hosts，不要盲目关闭检查。

## 自动安装 Docker

工具发现没有 Docker 时执行的等价命令：

```bash
sudo apt-get -o DPkg::Lock::Timeout=120 update
sudo apt-get -o DPkg::Lock::Timeout=120 install -y docker.io ca-certificates curl
sudo systemctl enable --now docker
sudo systemctl enable ssh
sudo docker info
```

已存在 Docker 时保留现有安装。远端执行仍使用 sudo/root，不依赖刚加 docker 组后的会话刷新，也不会为了方便而开放 Docker TCP 端口。

## 图形界面、永不休眠与性能

勾选关闭图形登录后，工具记录原 target 和显示管理器状态，然后执行：

```bash
sudo systemctl set-default multi-user.target
sudo systemctl stop display-manager
```

当前图形会话会退出；SSH 服务和网络不关闭。恢复原设置用“状态与主备切换”中的“恢复主机设置”。不自动重启机器。

勾选同一行的“永不休眠”，会记录以下目标的原状态，然后执行：

```bash
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target suspend-then-hibernate.target
```

该设置阻止系统实际进入睡眠、挂起、休眠，重启后仍有效；不用重新启动 logind，也不需要重启整机。恢复时只撤销工具新增的屏蔽，原本就被禁用的目标保持禁用。它不修改屏幕亮度或显示器熄屏设置。

性能模式优先使用系统提供的 `powerprofilesctl performance`；不支持时检查 cpufreq 是否支持 `performance` governor。虚拟机没有这些接口会明确跳过。直接设置 governor 的效果不保证重启后保留，重启后需要重新应用；不会修改 BIOS、超频或关闭 CPU 安全机制。
