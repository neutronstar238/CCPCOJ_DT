# CSGArena 赛场管控部署

部署工作台新增「管控服务端」「管控选手端」两个独立页面；「本地部署」位于导航最前。CSGArena 程序本身没有修改。

## 准备本地控制端

1. 在 Windows 安装并启动 WSL Linux 发行版，页面默认 `Ubuntu-24.04`。填写实际发行版名。
2. 在该发行版准备 Python 3.11+ 和 venv。Ubuntu 缺少 venv 时，在 WSL 终端执行 `sudo apt install python3-venv`。
3. 点击「准备本地 Ansible（需外网）」。依赖仅安装在本地 WSL：`~/.local/share/csgoj-ansible/venv`，Windows collection 安装到 Ansible 用户目录。不会在目标机器上下载依赖或安装包。
4. 点击「检查 Ansible 环境」，查看版本、SSH / WinRM 依赖和 Windows 模块检查结果。

Python 依赖范围：ansible-core 2.19.x、paramiko 3.5.x、pywinrm 0.5.x；collection 为 ansible.windows 3.x。已有控制端也可直接使用 PATH 中的 ansible-playbook，但上述模块必须齐全。

Linux 目标须已启用 SSH、安装 Python 3 和 systemd。使用选定 WSL 用户的 known_hosts，部署不会自动接受陌生主机密钥。首次连接前请核实指纹并通过该 WSL 用户完成 SSH 信任。登录用户名可为 root；其他用户根据配置通过 sudo 或 su 提权。提权密码为空时使用登录密码。

Windows 目标须提前启用 WinRM HTTPS（默认 5986）、允许连接端口并使用有管理员权限及提升令牌的账号。当前采用 NTLM，保留证书验证；证书须由 WSL 信任的 CA 签发，且包含目标 IP 的 SAN。此版本不自动开启远程管理，不关闭证书校验，不支持 WinRM HTTP。不能将远程桌面 RDP 端口填入这里。

## 服务端

- 可以添加多个单 IP 条目，每条独立设置系统、登录端口、用户名、密码和 Linux 提权方式／密码。
- **登录端口**连接操作系统；**管控业务端口**供选手端登记，默认 `39721`。
- 业务协议默认 HTTPS；选手端自动继承所绑定服务端的 IP、业务端口和协议。
- Linux 通过 systemd 的 `csgarenad.service` 启动、开机自启及失败重启。Windows 通过 SYSTEM 身份的计划任务 `CSGArenaServer-DeployConsole` 启动和开机自启。
- Linux 数据目录 `/opt/csgarena-deploy/server-data`；Windows 数据目录 `C:\ProgramData\CSGArenaDeploy\server-data`。
- 首次部署创建最小配置并开启登记；保留产品默认安全设置。管理员初始化仍在服务端本机管理页面完成，不会把操作系统登录密码当成管控管理密码。
- 重复部署保留 server.json 和业务数据。已有配置的业务端口／协议与页面不符时会失败并保留原配置，不会覆盖管理凭据。非本工具创建的同名 systemd 单元或计划任务不会被覆盖。

## 从场控服务端部署选手机

DT 默认使用 CSGArena v1.16.2。已有配置可在「版本选择与本地安装包缓存」明确选择并应用新版本。

1. 在 DT「管控服务端」配置服务端的 HTTPS 业务地址，预览目标并部署启动。初次安装需在服务端本机初始化可写管理员。
2. 在 DT「管控选手端」按已保存的服务端名称和地址打开控制台。服务端本机需具备 Ansible 环境，Windows 服务端使用自己的默认 WSL 发行版。
3. 在场控「环境与镜像」公开对应平台的客户端。要自动登记并启动，选手机镜像须已运行引导程序，并预置本场 HTTPS 地址与证书指纹。
4. 到场控「批量部署」配置目标 IP 段、系统和凭据，分发与公开版本相同的客户端。先核对分发回执，再核对「机位总览」的新心跳。已在线旧客户端的心跳不能单独证明升级完成。
5. 尚未预置引导程序的机器只收到文件。需要使用原有安装路径时，展开 DT「通过 DT 直接部署选手端（兼容流程）」。

## 通过 DT 直接部署选手端（兼容流程）

### 扫描后批量导入机位

「管控选手端」兼容流程中提供扫描区。填写起始、结束完整 IPv4，可添加多组范围，例如 `192.168.1.20 — 192.168.1.200`。跨网段也支持，重复地址自动合并；每次最多 4096 个地址，排除尾号 0 / 255 以匹配部署编辑器。

扫描从运行工作台的 Windows 电脑发起，最多 32 个并发探测，检查 SSH / WinRM HTTPS 端口（默认 22 / 5986，可修改），必要时补 ICMP 探测。它不会尝试登录、安装或登记。支持进度、响应数量及停止按钮；扫描期间其他部署任务互斥。

TCP 可连接、TCP 拒绝或 ICMP 回复视为有在线响应；无回应不能证明关机，网络设备／防火墙也可能影响结果。系统类型仅由管理端口提供建议，不是操作系统识别结论。默认只勾选所选管理端口可连接的机器；仅有 ICMP / 拒绝响应的机器可手动勾选，但部署前仍需启用 SSH / WinRM。

扫描完成后填写统一账号、密码与登记服务端，默认 **sudo 密码就是各机登录密码**。勾选「另外设置统一 sudo 密码」可统一指定；结果表也支持单机账号、密码、sudo 密码、系统、端口及服务端覆盖。单机字段留空继承统一设置，sudo 也为空时最终使用该机登录密码。

点击「加入选手端部署清单」，仅加入勾选的响应 IP；已有服务端或选手端 IP 跳过，未响应的间隔 IP 不会补入。加入清单不会安装，核对下方完整目标清单后点击「一键部署并登记」。部署作用于下方清单的全部目标，沿用 Ansible 分发、客户端 setup、自启动和本机向导自动登记；每台独立生成身份。

扫描结果是本次工作台进程内的临时清单。凭据不进入扫描请求，统一输入框不写入浏览器存储；导入部署清单并保存后才通过工作台 DPAPI 持久化。账号密码不会被发送到仅用于网络探测的主机。

### 手动添加范围

1. 先添加服务端，再在「管控选手端」添加 IP 段。
2. 地址形式为 `192 . 168 . 1 . 20 — 192 . 168 . 1 . 50`；结束地址前三段只读并自动同步，尾段含起止值。跨网段请添加下一条。单台选手机可填写相同起止尾号。
3. 每段可独立设置 Linux／Windows、登录端口、用户名、密码、Linux 提权信息，并选择一个服务端。
4. 点击「预览目标清单」核对展开后的 IP、系统、登录账号和登记端点。重复 IP、重叠区间、无效绑定、倒序范围会被拒绝；整个配置上限 4096 台。
5. 点击「一键部署并登记」。先把该页所需的所有产物准备在本地，之后才接触远端。客户端通过自己的本机向导 API 探测并登记，每台独立生成密钥和登记身份。

此流程执行产品现有 `setup`，会安装系统服务和产品自启动配置。须在赛场机或隔离测试机使用，不在日常工作机上运行验收。Linux 检查 `csgarena` 和 `csgarena-watch`，Windows 检查 `CSGArena` 和 `CSGArenaWatch`。API 同时报告 enrolled、installed 成功后才记录安装结果。

本工具已登记、相同产物且相同服务端的机器，重复部署会保留原身份并检查服务状态。已有身份但没有本工具登记记录、绑定变化或更换客户端产物时，停止并提示使用管控产品维护／升级流程；不重新登记、不清除密封状态。登记成功但自启动失败的机器保留现场，需通过维护流程修复后再验收。

## 安装包、本地缓存和结果

### 扫描全部 Releases 并选择版本

两页都提供「扫描全部 Releases」，按每页 100 条读完当前 GitHub 账号可见的所有分页，不限于 latest 或第一页。列表显示正式版、预发布及草稿；四种标准安装包或 SHA256 不齐全、命名不受支持及草稿版本会列出原因并禁用选择。任意后续页失败会报告扫描失败，不把部分结果当作完整列表。

扫描只更新版本列表，不改变已有来源，也不自动选中最新版。选择指定版本，点击「应用所选版本」重新读取该版本的四种文件和 SHA256，再保存。仅切换下拉选择而未应用时，拉取／推送／部署会被拦截，避免操作上次应用的版本。

- **拉取本页安装包到本地**：可在未添加目标时执行，同时缓存本页 Linux / Windows 两种产物；服务端页下载服务端，选手端页下载选手端。
- **仅推送所选版本**：根据本页全部目标的系统，从校验后的本地缓存通过 Ansible 复制到各机暂存目录。日志列出配置版本、目标路径及 SHA256；不执行 setup，不替换现有运行程序、不重新登记。目标仍需正确的管理连接、凭据和提权权限。
- **一键部署并启动／登记**：继续执行安装启动与首次登记；已有选手端更换版本或绑定仍受产品维护流程限制。仅推送成功不代表已更新正在运行的选手端。

暂存目录仍为 Linux `/opt/csgarena-deploy`、Windows `C:\ProgramData\CSGArenaDeploy`，文件以 SHA256 命名，不同版本可共存；它们是版本化本地缓存对应的目标副本。

- Linux／Windows 的服务端／选手端共四种产物配置，按目标系统选择实际需要的项。
- 已预置 [SZTU-ACM/CSGArena v1.16.2](https://github.com/SZTU-ACM/CSGArena/releases/tag/v1.16.2) 的四个地址及 GitHub 资产 SHA256。旧配置中的空产物会补上默认值，已有自定义来源保留。支持 Windows 本地完整文件路径，也支持 HTTPS 下载链接；当前适配单文件 ELF / EXE，不解包 ZIP。
- 文件名规范为 `csgarena_server_linux_amd64_v1.16.2`、`csgarena_server_windows_amd64_v1.16.2.exe`、`csgarena_client_linux_amd64_v1.16.2`、`csgarena_client_windows_amd64_v1.16.2.exe`。固定仓库为 `SZTU-ACM/CSGArena`，下载地址为 `https://github.com/SZTU-ACM/CSGArena/releases/download/版本号/文件名`。
- 输入版本号或该仓库 Release 链接，点击「读取并应用到四种产物」：必须四个文件名及 GitHub SHA256 全部匹配才更新页面；会替换四项地址和校验值、清空本地路径，但保留目标 IP 和登录凭据。点击保存后生效，不自动切换到 latest。
- 匿名 API 或下载返回 403／404 时，自动使用当前 Windows 用户已登录的 GitHub CLI。先安装 `gh` 并执行 `gh auth login`，账号须有仓库权限；令牌由 gh 管理，工作台不读取或保存令牌。自动认证只用于该仓库的标准资产路径，不用于任意自定义 URL。登录下载后仍必须校验 SHA256。
- 下载必须填写发布方 SHA256；本地文件可省略，由工作台计算。若同时有本地路径和链接，优先本地文件。
- 缓存在工作台资料目录 `arena-cache`，文件名包含类型和 SHA256。明确填写 SHA256 后可断网复用校验通过的缓存，即使原本地文件已移动。
- 在「仅准备本地缓存」成功后可进行内网部署；目标机器不会访问下载地址。系统依赖、WinRM 配置和业务防火墙应在赛前提前准备。
- 所有主机凭据单独保存在 `arena.dpapi`，由当前 Windows 用户 DPAPI 加密。不会保存到浏览器 localStorage 或导出进程参数。Ansible inventory 经标准输入传入 WSL，只在私有临时目录落盘，正常退出及失败后清理。
- 不同系统分组执行，每组最多 10 台并行；Ansible recap 标明每台 IP 的成功、失败或不可达。失败不会回滚其他已成功机位，可修复原因后重试。
- 「查询开启状态」不需要安装包，只读检查服务／任务状态，服务端另检查本机业务端口监听。查询完成不等于所有主机已开启，须看各机 JSON 中的 running / services / listening。它也不等于选手心跳、截图和考试策略均通过，最终需在服务端检查机位在线并完成实际赛场验收。
- 请保持工作台运行到任务结束；当前没有强制中断安装／自动卸载入口。直接终止 WSL 可能留下私有临时目录，须由同一 WSL 用户检查清理。

## 开发验证范围

v1.14.2 起，SSH 推送、部署和状态查询会先握手核对主机公钥。复用 Windows 用户 `.ssh/known_hosts`、工作台 `known_hosts` 和 `arena_known_hosts` 中的信任记录。首次目标在页面显示地址、算法和 SHA256 指纹，点击「确认首次指纹并继续」后才登录并执行原任务；配置变化或过期任务不能沿用旧确认。已有指纹不一致时拒绝连接，不覆盖旧记录。确认后的公钥经标准输入传给 WSL，在任务私有 HOME 的 `.ssh/known_hosts` 使用并随任务清理，不修改 WSL 用户的信任文件，也不关闭主机密钥检查。

自动测试覆盖 IP 展开／区间校验、服务端绑定、缓存校验／损坏拒绝、凭据隔离、鉴权接口、任务互斥和页面输入同步。Ansible playbook 另做语法检查。尚未获得用户最终发布包和隔离的 Linux／Windows 赛场目标，因此不能把这些检查视为实机安装、登记或策略验收完成。
